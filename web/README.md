# web

The single-page UI served by `continuum-ui` (`proxy` in front of a live
engine, `serve --log` over a recorded run): React 19, TypeScript and Vite,
styled with Tailwind CSS v4 and shadcn/ui components on Radix primitives.
The engine binary, `continuum`, does not link this package (an archtest rule
holds it), so a UI change never changes the engine image.

- `web.go`: embeds `dist/` and serves it; paths without an extension fall back
  to `index.html` so client routes survive a reload.
- `index.html`, `vite.config.ts`, `tsconfig.json`, `package.json`: the build.
  `npm run dev` proxies `/api` to `127.0.0.1:8088`. `@/` imports resolve to
  `src/`.
- At startup the UI comes up before the engine: `src/views/startup.tsx` polls
  `/api/_ui/status` (answered by `continuum-ui proxy` itself), shows one
  "devnet is starting" banner and keeps each view's normal layout with empty
  states instead of error banners until the engine answers. Servers without
  that route (`continuum-ui serve`) behave as before.
- `components.json`: the shadcn/ui CLI's settings (where components go, which
  CSS file holds the tokens).
- [`src/`](src/README.md), [`test/`](test/README.md).
- `public/`: static files Vite copies into `dist/` unchanged (`favicon.svg`). It has no README because Vite would copy that into `dist/` and serve it too.
- `dist/` (and `dist/assets/`): build output, committed so `go build` needs no
  Node. Regenerated by `make web`; do not edit.

`make web` rebuilds `dist/`; `make web-test` typechecks and runs Vitest. Both
need Node 22.12 or later and npm. Everything is bundled: the page loads
nothing from a CDN, so it works offline behind `continuum-ui`. Every
dependency is pinned to an exact version.

## Styling

Style an element with Tailwind utilities on the element itself, or use a
component that does. There are no global element rules beyond Tailwind's
preflight and the two in `src/index.css` (border colour, page background), so
a rule written for one table or label cannot leak into another.

Colours are the tokens in `src/index.css`, in shadcn/ui's names (`bg-card`,
`text-muted-foreground`, `border-border`, `text-destructive`) plus `ok`,
`warn` and `chart-a/b/c`. Dark mode is `[data-theme="dark"]` on `<html>`, set
by the theme toggle; `dark:` utilities follow it. Use the tokens rather than
raw colours so both themes stay readable.

## Adding a shadcn/ui component

From `web/`, run `npx shadcn@4.23.1 add <component>` (it reads
`components.json` and writes `src/components/ui/<component>.tsx`), or copy the
component's source from the shadcn/ui site into that directory by hand. Then:

1. Pin any new dependency it brings to an exact version in `package.json`
   and check its licence is MIT, ISC, Apache-2.0 or BSD.
2. Swap colour classes that do not exist here for the tokens above.
3. `npm run build` and commit `src/components/ui`, `package.json`,
   `package-lock.json` and `dist/` together.

Prefer a native element where shadcn/ui has one: filter dropdowns use
`NativeSelect`, which keeps the browser's listbox and lets the empty "All"
value through.
